# Tasks: Views Layer Between Apps and Features

**Input**: Design documents from `/specs/005-views-layer/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/

**Tests**: Included. Each PR carries MSW-backed hook tests, component tests, Storybook stories with visual snapshots in a fixed-size box (ADR-009) and keeps the existing e2e suite green.

**Organization**: PR 1 (this one) is the documents. The remaining work is one phase per stacked PR, PR 2 to PR 7 (the user-preferences work, T050 to T055, is deferred and parked on `ACC-3216-user-preferences-parked`; this series is 7 PRs). Every task cites the requirement (FR) and contract it traces to (constitution Principle IX). A PR that departs from this list amends it in the same PR.

**Removed/merged**: the series originally stacked ten PRs, with a PR 3 for a shared `navigator-data` "target resolution" mechanism (`ViewTarget`, `ResolvedViewTarget`). Review concluded views should resolve their own data through `navigator-data`'s existing hooks instead, with no shared target type; that PR (and its tasks, T007–T012) is dropped, not deferred. A second round folded the collection view's state (originally its own PR 5) into the item detail view's PR, now PR 3, because the reference implementation (ACC-3216 PR #246) builds both views together, sharing the same by-name-or-by-link target hooks and breadcrumb components; PRs 6–9 are renumbered 5–8 below. Task IDs are kept as they were through both rounds, per this file's own task-ID stability, rather than renumbered — so PR 3's phase below contains T013–T020 and T016a (the original item detail tasks) followed by T027–T034 (the original collection-state tasks), not a contiguous range.

## Phase PR 4: strip layout from features

**Purpose**: features fill their space; views draw the page chrome. The item detail view already renders the body-only `EntityItemDetailBody` export instead of the full page component (PR 3), and the collection view already passes the collection feature its state directly (PR 3); this phase removes the now-unused `toolbar`/`breadcrumbs`/`actions` props and `PageLayout`/`BreadCrumbsToolBarLayout` wrapping from the full-page feature components themselves, so nothing in the features package can still be rendered as a forced full page. It goes one step further than layout-only stripping: the item component also drops its own `useEntityItem` call in favor of an already-loaded `item` prop, and the two self-fetching wrappers this made redundant (`EntityItemContentFocusView`, `EntityItemCollectionSearchView`) are removed outright rather than left as unused dead code. Review also settled that no component in `packages/features` carries the `View` suffix (only `packages/views` does), so this PR renames the feature components: `EntityItemView` to `EntityItemDetail`, `EntityItemCollectionView` to `EntityItemCollectionBrowser`, `CreateEntityItemView` to `CreateEntityItemPanel`, `ClassifyCreateEntityItemView` to `ClassifyCreateEntityItemPanel`, and the content-focus variation's `views/` folder to `body/`.

- [x] T021 [PR 4] Remove `toolbar`, `breadcrumbs`, `actions` props and the `PageLayout` and `BreadCrumbsToolBarLayout` wrapping from `EntityItemView` (renamed `EntityItemDetail`, `packages/features/src/entity-item/entity-item-detail.tsx`) and from the content-focus variation's `EntityItemDetailBody` (`variations/content-focus/body/`); go further than dropping layout props and also remove the item component's own `useEntityItem` call, so it takes an already-loaded `item: EntityItem` prop (plus an optional `refetch`) instead (the view above it resolves and owns loading); make the root fill its parent (`h-full min-h-0`, no outer padding, no window-sized units). The self-fetching, toolbar-drawing `EntityItemContentFocusView` wrapper (by `entityName`/`itemId`) is removed outright once the item detail view hands `EntityItemDetailBody` an already-loaded item directly — nothing else called it. Traces: FR-021, FR-024; contract `view-toolbar.md` rules 4, 5.
